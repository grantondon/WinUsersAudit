# WinUsersAudit — инструкции для Codex

Этот файл задаёт постоянные правила работы с репозиторием
`grantondon/WinUsersAudit`. Рабочая ветка проекта — `main`.

Перед изменениями обязательно прочитай:

- `README.md`;
- затрагиваемые функции `WinUsersAudit.vbs`;
- `docs/PROJECT_CONTEXT.md`;
- `docs/MAIN.md`;
- `docs/LOCAL_WORKFLOW.md`.

Если документация расходится с фактическим кодом, зафиксируй расхождение и
ориентируйся на актуальный код и поставленную задачу.

## 1. Совместимость сборщика

`WinUsersAudit.vbs` должен сохранять совместимость с:

- Windows XP SP2;
- Windows Server 2003;
- Windows 7;
- Windows 10;
- более новыми Windows, пока необходимые старые интерфейсы доступны.

Используй только VBScript/WSH-синтаксис и системные интерфейсы, совместимые со
старыми версиями Windows.

## 2. Разрешённые технологии

Разрешено использовать:

- Windows Script Host и VBScript;
- WMI;
- ADSI WinNT;
- COM;
- штатный доступ к реестру;
- `secedit.exe`;
- `netstat.exe`;
- `route.exe`, если нужен резервный способ;
- `ping.exe` там, где он уже используется;
- `WinHttp.WinHttpRequest.5.1`;
- `HNetCfg.FwPolicy2`;
- резервный `HNetCfg.FwMgr`;
- `Shell.Application`;
- стандартные объекты `Scripting.FileSystemObject`, `WScript.Shell` и
  `WScript.Network`.

## 3. Запрещённые зависимости

На проверяемом Windows-компьютере нельзя требовать:

- PowerShell;
- .NET;
- WMIC;
- curl;
- Python;
- сторонние программы;
- дополнительные установки.

PowerShell допустим только во вспомогательном сценарии локальной проверки
`tools/Test-LocalAudit.ps1` и не является зависимостью сборщика.

## 4. Основные правила

- Не переписывай рабочий код с нуля без необходимости.
- Сохраняй существующий функционал, если задача прямо не требует изменения.
- Ошибка одного раздела по возможности не должна останавливать остальные.
- Недоступное значение не подменяй значением `Нет`, `0` или пустой строкой без
  оснований.
- Различай `Не определено`, `Не задан`, `Не применимо`, `0` и `False`.
- Не делай вывод о наличии пароля по полю `Пароль требуется?`.
- Не считывай пароли и хэши паролей.
- IPv6 сейчас не является целью проекта.
- Избегай разбора локализованного вывода команд, если данные доступны через
  WMI, ADSI, COM или реестр.
- При неизбежном разборе консольного вывода проверяй устойчивость к версиям ОС
  и локали.
- Пользовательских ключей запуска у скрипта нет.

## 5. Выходные файлы

Сборщик создаёт рядом со скриптом:

- `<hostname>_user.csv`;
- `<hostname>_int.csv`;
- `<hostname>_route.csv`;
- `<hostname>_netstat.csv`;
- `<hostname>_software.csv`;
- `<hostname>_diag.log`;
- `<hostname>.zip`.

ZIP содержит пять CSV и диагностический журнал. Исходные файлы сохраняются.

## 6. Кодировки и формат

- `WinUsersAudit.vbs` и `WinUsersAudit_README.txt` хранятся в UTF-16 LE с BOM.
- CSV и `_diag.log` создаются в UTF-16 LE с BOM.
- CSV-разделитель — `;`.
- Каждое значение CSV заключается в двойные кавычки.
- Не пересохраняй production-файлы в несовместимой кодировке.

## 7. Перед изменением

1. Проверь текущую ветку, удалённый репозиторий и локальные изменения.
2. Прочитай актуальную документацию и затрагиваемые функции.
3. Перечисли, какие существующие данные, файлы или схемы изменятся.
4. Сохрани пользовательские изменения, не относящиеся к задаче.

## 8. После изменения

1. Выполни статические проверки структуры VBScript и кодировок.
2. Запусти `tools/Test-LocalAudit.ps1` на Windows с повышенными правами.
3. Проверь консоль, пять CSV, диагностический журнал и содержимое ZIP.
4. Отдельно проверь изменённую функциональность.
5. При ошибках исправь код и повтори запуск.
6. Сверь SHA-256 опубликованного файла с успешно проверенным экземпляром.
7. Не отправляй в GitHub отчёты аудита и каталог `.local-validation/`.
8. Коммит и публикация разрешены только после успешной проверки.

Если исполняемый код не менялся, повторный запуск сборщика не требуется, но
необходимо подтвердить неизменность его SHA-256.

## 9. Итоговое сообщение

Укажи:

- ветку;
- изменённые и удалённые файлы;
- затронутые функции и схемы;
- влияние на Windows XP/Server 2003;
- выполненные проверки;
- что не проверялось на реальной Windows.
