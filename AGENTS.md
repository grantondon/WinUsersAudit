# WinUsersAudit — инструкции для Codex

Этот файл задаёт постоянные правила работы с репозиторием `grantondon/WinUsersAudit`.

Перед любыми изменениями обязательно прочитай:

- `README.md` текущей ветки;
- `WinUsersAudit.vbs`;
- `docs/PROJECT_CONTEXT.md`;
- `docs/MAIN.md`;
- `docs/UNIFIED_REPORT.md`.

Если документация расходится с фактическим кодом текущей ветки, сначала зафиксируй расхождение и ориентируйся на актуальный код и поставленную задачу. Не возвращай старое поведение только потому, что оно упомянуто в историческом контексте.

## 1. Ветки проекта

В репозитории две независимо развиваемые ветки:

- `main` — классическая версия, создающая отдельные CSV, диагностический лог и ZIP;
- `unified-report` — экспериментальная версия с единым контейнером WUA1 и отдельным Python-парсером.

Не смешивай архитектуры двух веток.

При работе в `unified-report`:

- не изменяй `main`;
- не сливай `unified-report` в `main`;
- не создавай PR в `main`;
- не используй `main` для промежуточных коммитов unified-report.

Перед изменением файлов всегда проверь текущую ветку.

## 2. Совместимость сборщика

`WinUsersAudit.vbs` должен сохранять совместимость с:

- Windows XP SP2;
- Windows Server 2003;
- Windows 7;
- Windows 10;
- более новыми Windows, пока необходимые старые интерфейсы доступны.

Используй только VBScript/WSH-синтаксис и системные интерфейсы, совместимые со старыми ОС.

## 3. Разрешённые технологии для сборщика

Разрешено:

- Windows Script Host;
- VBScript;
- WMI;
- ADSI WinNT;
- COM;
- штатный доступ к реестру;
- `secedit.exe`;
- `netstat.exe`;
- `route.exe`, если нужен резервный способ;
- `ping.exe` там, где он уже используется;
- `WinHttp.WinHttpRequest.5.1`;
- `HNetCfg.FwPolicy2`;
- резервный `HNetCfg.FwMgr`;
- `Shell.Application`;
- стандартные объекты `Scripting.FileSystemObject`, `WScript.Shell`, `WScript.Network`.

## 4. Запрещённые зависимости для сборщика

На проверяемом Windows-компьютере нельзя требовать:

- PowerShell;
- .NET;
- WMIC;
- curl;
- Python;
- сторонние программы;
- дополнительные установки.

Исключение: Python используется только внешним парсером ветки `unified-report`, а не сборщиком на проверяемом ПК.

## 5. Общие принципы

- Не переписывай рабочий код с нуля без необходимости.
- Сохраняй существующий функционал, если задача прямо не требует его изменения.
- Ошибка одного раздела по возможности не должна останавливать остальные.
- Недоступное значение не подменяй значением `Нет`, `0` или пустой строкой без оснований.
- Различай `Не определено`, `Не задан`, `Не применимо`, `0` и `False`.
- Не делай вывод о наличии пароля по полю `Пароль требуется`.
- Не считывай пароли и хэши паролей.
- IPv6 сейчас не является целью проекта.
- Избегай разбора локализованного вывода команд, если данные доступны через WMI/ADSI/COM/реестр.
- При неизбежном разборе консольного вывода проверяй устойчивость к версиям ОС и локали.

## 6. Кодировки

Ветка `main`:

- `WinUsersAudit.vbs` и TXT-инструкция в репозитории рассчитаны на UTF-16 LE с BOM;
- CSV и `_diag.log` создаются в UTF-16 LE с BOM;
- CSV: `;`, каждое значение в двойных кавычках.

Ветка `unified-report`:

- WUA1: UTF-16 LE с BOM, CRLF;
- экспортируемые парсером CSV: UTF-16 LE с BOM, CRLF, `;`, двойные кавычки.

Не пересохраняй production-VBScript в кодировке, несовместимой со старыми Windows.

## 7. Правило «текущий код важнее истории»

Документы `PROJECT_CONTEXT.md`, `MAIN.md`, `UNIFIED_REPORT.md` описывают фактическое состояние текущих веток на момент подготовки контекста.

Исторические идеи, которые ещё не реализованы, не считаются текущим функционалом.

Примеры:

- `main` сейчас создаёт пять CSV, включая `_software.csv`;
- `_int.csv` в текущем `main` содержит 15 колонок;
- `unified-report` сейчас не содержит типа SOFTWARE;
- текущий `parse_wua_logs.py` создаёт `password_policies.csv`;
- отдельный `systems.csv` парсер не создаёт.

## 8. Перед изменением

Перед правкой:

1. проверь ветку;
2. прочитай актуальный `README.md`;
3. прочитай затрагиваемые функции `WinUsersAudit.vbs`;
4. для unified-report дополнительно прочитай `parse_wua_logs.py` и тесты;
5. перечисли, какие существующие данные/файлы/схемы изменятся.

## 9. После изменения

В итоговом сообщении укажи:

- ветку;
- изменённые файлы;
- изменённые функции или схемы;
- влияние на XP/2003;
- новые fallback-механизмы;
- изменения выходных файлов;
- изменения схем CSV/WUA1;
- какие тесты выполнены;
- что не было проверено на реальной Windows.

Не заявляй о проверенной совместимости с XP/2003, если реальный запуск не выполнялся.
