# AGENTS.md

# WinUsersAudit — инструкции для Codex

Этот файл задаёт постоянные правила работы с репозиторием
`grantondon/WinUsersAudit`. Рабочая ветка проекта — `main`.

## 1. Принцип минимального контекста

Перед изменениями обязательно прочитай:

- `AGENTS.md`;
- непосредственно затрагиваемые функции и места их вызова в `WinUsersAudit.vbs`.

Остальную документацию читай только по необходимости:

- `docs/MAIN.md` — когда требуется понять текущую реализацию, формат отчётов,
  взаимодействие подсистем или технические особенности конкретного раздела;
- `docs/PROJECT_CONTEXT.md` — когда задача затрагивает назначение, общую
  архитектуру или ограничения проекта;
- `docs/LOCAL_WORKFLOW.md` — когда выполняется локальная разработка,
  тестирование или публикация;
- `README.md` и `WinUsersAudit_README.txt` — когда изменение влияет на
  пользовательскую документацию.

Не перечитывай файлы и разделы, не относящиеся к задаче. При поиске реализации
сначала находи конкретные процедуры, функции, константы и места их вызова.
Расширяй область анализа только при обнаружении зависимости или недостатке
информации.

Не выполняй полный повторный аудит `WinUsersAudit.vbs`, README и всей
документации для локального изменения без технической необходимости.

Если документация расходится с фактическим кодом, зафиксируй расхождение и
ориентируйся на актуальный код и поставленную задачу.

## 2. Совместимость сборщика

`WinUsersAudit.vbs` должен сохранять совместимость с:

- Windows XP SP2;
- Windows Server 2003;
- Windows 7;
- Windows 10;
- более новыми Windows, пока необходимые старые интерфейсы доступны.

Используй только VBScript/WSH-синтаксис и системные интерфейсы, совместимые со
старыми версиями Windows.

## 3. Разрешённые технологии

Разрешено использовать:

- Windows Script Host и VBScript;
- WMI;
- ADSI WinNT;
- COM;
- штатный доступ к реестру;
- `secedit.exe`;
- `netstat.exe`;
- `route.exe`, если нужен резервный способ;
- `ping.exe` там, где он уже используется;
- `WinHttp.WinHttpRequest.5.1`;
- `HNetCfg.FwPolicy2`;
- резервный `HNetCfg.FwMgr`;
- `Shell.Application`;
- стандартные объекты `Scripting.FileSystemObject`, `WScript.Shell` и
  `WScript.Network`.

## 4. Запрещённые зависимости

На проверяемом Windows-компьютере нельзя требовать:

- PowerShell;
- .NET;
- WMIC;
- curl;
- Python;
- сторонние программы;
- дополнительные установки.

PowerShell допустим только во вспомогательном сценарии локальной проверки
`tools/Test-LocalAudit.ps1` и не является зависимостью сборщика.

## 5. Основные правила

- Не переписывай рабочий код с нуля без необходимости.
- Сохраняй существующий функционал, если задача прямо не требует изменения.
- Делай минимальные изменения в существующей архитектуре.
- Не изменяй существующие имена, состав и форматы выходных файлов, если это
  прямо не требуется задачей. Актуальное состояние описано в
  `docs/MAIN.md`, но при расхождении источником истины является код.
- Ошибка одного раздела по возможности не должна останавливать остальные.
- Недоступное значение не подменяй значением `Нет`, `0` или пустой строкой
  без оснований.
- Различай `Не определено`, `Не задан`, `Не применимо`, `0` и `False`.
- Не делай вывод о наличии пароля по полю `Пароль требуется?`.
- Не считывай пароли и хэши паролей.
- IPv6 сейчас не является целью проекта.
- Избегай разбора локализованного вывода команд, если данные доступны через
  WMI, ADSI, COM или реестр.
- При неизбежном разборе консольного вывода проверяй устойчивость к версиям ОС
  и локали.
- Пользовательских ключей запуска у скрипта нет.

## 6. Кодировки и формат

- `WinUsersAudit.vbs` и `WinUsersAudit_README.txt` хранятся в UTF-16 LE с BOM.
- CSV и `_diag.log` создаются в UTF-16 LE с BOM.
- CSV-разделитель — `;`.
- Каждое значение CSV заключается в двойные кавычки.
- Не пересохраняй production-файлы в несовместимой кодировке.

## 7. Перед изменением

1. Проверь текущую ветку, удалённый репозиторий и локальные изменения.
2. Прочитай `AGENTS.md`, затрагиваемые функции и только необходимую для задачи
   дополнительную документацию.
3. Определи, какие существующие данные, файлы или схемы реально затрагиваются.
4. Сохрани пользовательские изменения, не относящиеся к задаче.

## 8. Проверка после изменения

### Если изменялся `WinUsersAudit.vbs`

1. Выполни статические проверки структуры VBScript и кодировок.
2. Сначала проверь непосредственно изменённую функциональность.
3. Перед публикацией выполни `tools/Test-LocalAudit.ps1` на Windows с
   повышенными правами.
4. Проверь консоль, все создаваемые CSV, диагностический журнал и содержимое ZIP.
5. При ошибках исправь код и повтори необходимые проверки.
6. Сверь SHA-256 опубликованного файла с успешно проверенным экземпляром.
7. Не отправляй в GitHub отчёты аудита и каталог `.local-validation/`.
8. Коммит и публикация исполняемого кода разрешены только после успешной
   проверки.

### Если менялась только документация

- запуск сборщика и полный аудит не требуются;
- проверь согласованность изменённой документации с актуальным кодом и другими
  непосредственно связанными документами;
- подтверди, что `WinUsersAudit.vbs` не изменился.

Не запускай полный цикл проверки только ради изменения документации.

## 9. Итоговое сообщение

Укажи:

- ветку;
- изменённые и удалённые файлы;
- затронутые функции и схемы;
- влияние на Windows XP/Server 2003;
- выполненные проверки;
- что не проверялось на реальной Windows.
