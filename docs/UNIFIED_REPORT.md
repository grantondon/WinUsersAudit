# UNIFIED_REPORT.md

# WinUsersAudit — фактическое состояние ветки `unified-report`

Документ составлен по текущим:

- `README.md`;
- `WinUsersAudit.vbs`;
- `parse_wua_logs.py`;
- `tests/test_parse_wua_logs.py`.

## 1. Назначение

`unified-report` — отдельная экспериментальная ветка.

Вместо классических CSV и ZIP сборщик создаёт один структурированный лог WUA1.

Ветка развивается независимо от `main`.

## 2. Файлы ветки

Основные файлы:

- `WinUsersAudit.vbs` — сборщик на проверяемом Windows-хосте;
- `parse_wua_logs.py` — внешний парсер множества WUA1-логов;
- `tests/test_parse_wua_logs.py` — автоматические тесты парсера и части контрактов сборщика;
- `WinUsersAudit_README.txt` — инструкция для старых Windows;
- `README.md`.

## 3. Выход сборщика

Финальный файл:

`<hostname>_YYYYMMDD_HHMMSS.wua.log`

Во время выполнения:

`<hostname>_YYYYMMDD_HHMMSS.wua.partial`

После записи `END` и успешного закрытия `.partial` переименовывается в `.log`.

При аварии `.partial` остаётся.

Совпавшее имя не перезаписывается — используется числовой суффикс.

Классические:

- `_user.csv`;
- `_int.csv`;
- `_route.csv`;
- `_netstat.csv`;
- `_diag.log`;
- ZIP

в основном unified-пути не создаются.

## 4. Ключи сборщика

Поддерживаются:

`/debug`

`/nolog`

Поведение:

- обычный запуск и `/debug` сохраняют подробные INFO;
- `/nolog` не отключает WUA1, а только убирает необязательные INFO;
- FILE, SCHEMA, DATA, WARNING, ERROR и END сохраняются;
- если указаны `/debug` и `/nolog`, приоритет у `/nolog`;
- неизвестный ключ фиксируется как WARNING.

Также в коде есть внутренний password-age worker, используемый дочерним `cscript`.

## 5. Формат WUA1

Кодировка:

- UTF-16 LE с BOM;
- CRLF.

Разделитель:

`;`

Все значения в двойных кавычках.

Перед CSV-кодированием специальные символы экранируются:

- `\` → `\\`
- CR → `\r`
- LF → `\n`
- TAB → `\t`

Каждая физическая строка начинается с `WUA1`.

## 6. Виды записей

Поддерживаются:

- `FILE`
- `SCHEMA`
- `DATA`
- `EVENT`
- `END`

### FILE

Содержит метаданные запуска, в том числе:

- версия формата;
- run ID;
- hostname;
- начало запуска;
- версия WinUsersAudit;
- ОС;
- версия ОС;
- WSH;
- часовой пояс;
- учётная запись;
- административные права.

### SCHEMA

Пишется перед первой DATA соответствующего типа/версии.

Версии схем независимы для типов.

### DATA

Число значений должно совпадать с SCHEMA.

### EVENT

Уровни:

- INFO;
- WARNING;
- ERROR.

Подсистемы включают:

- STARTUP;
- SYSTEM;
- USER;
- PASSWORD_POLICY;
- SECEDIT;
- INTERFACE;
- ROUTE;
- FIREWALL;
- CONNECTION;
- PING;
- HTTP;
- FILE;
- FINISH.

### END

Статусы:

- COMPLETE;
- COMPLETE_WITH_WARNINGS;
- PARTIAL;
- FAILED.

## 7. Текущие DATA-типы

Текущий сборщик использует:

- `SYSTEM`
- `USER`
- `PASSWORD_POLICY`
- `INTERFACE`
- `ROUTE`
- `FIREWALL_PROFILE`
- `CONNECTION`
- `PING`
- `HTTP`

Диагностика идёт через `EVENT`.

### Важно

Текущая `unified-report` **не имеет типа SOFTWARE** и не собирает установленное ПО аналогично текущему `main`.

Это реальное функциональное расхождение веток.

## 8. Схемы

По текущему README:

- `USER` — схема 2;
- `PING` — схема 2;
- остальные текущие DATA-типы — схема 1.

Парсер объединяет разные версии схем по именам колонок.

## 9. USER

Текущий `USER` содержит:

- идентификатор запуска;
- время сбора;
- 13 базовых пользовательских полей;
- 5 параметров парольной политики.

То есть политика частично дублируется в каждой записи USER.

Возраст пароля читается через ADSI WinNT `PasswordAge` отдельным дочерним `cscript` с тайм-аутом 30 секунд.

## 10. PASSWORD_POLICY

Отдельный тип всё ещё существует.

Он содержит параметры и диагностику получения политики, включая сведения `secedit`.

Следовательно, текущее состояние ветки отличается от поздней идеи полностью отказаться от отдельного `password_policies.csv`.

## 11. INTERFACE

По текущему unified README тип содержит 19 сетевых полей плюс служебные поля запуска/времени.

IPv6 исключён.

Это отличается от текущего `main`, где `_int.csv` сейчас имеет 15 колонок.

## 12. ROUTE

Содержит IPv4-маршруты, интерфейс, метрику и источник.

## 13. FIREWALL_PROFILE

Сначала используется:

`HNetCfg.FwPolicy2`

При недоступности выполняется fallback:

`HNetCfg.FwMgr`

В данные попадают профильные параметры, сведения службы и COM-источник.

## 14. CONNECTION

Снимок IPv4 TCP/UDP.

Текущие данные включают:

- run ID;
- hostname;
- время;
- протокол;
- локальный адрес/порт;
- удалённый адрес/порт;
- состояние;
- PID;
- имя процесса;
- путь;
- владельца.

Командная строка не собирается.

`netstat` запускается с тайм-аутом 30 секунд.

## 15. PING

Текущий `PING` использует `Win32_PingStatus`.

Пять IPv4-адресов:

- `1.1.1.1`
- `8.8.8.8`
- `9.9.9.9`
- `208.67.222.222`
- `77.88.8.8`

На каждый адрес формируется одна итоговая DATA-строка.

Текущая схема: 2.

## 16. HTTP

Пять URL:

- Microsoft connect test;
- Google connectivity check;
- Firefox captive portal check;
- example.com;
- neverssl.com.

Используется:

`WinHttp.WinHttpRequest.5.1`

Тайм-ауты:

- resolve 3000 мс;
- connect 3000 мс;
- send 3000 мс;
- receive 5000 мс.

Автоматические перенаправления отключаются.

## 17. Python-парсер

Файл:

`parse_wua_logs.py`

Требования:

- Python 3;
- только стандартная библиотека;
- Windows или Linux.

Парсер рекурсивно ищет WUA1-логи.

Режимы:

- `--all` — все допустимые запуски, режим по умолчанию;
- `--latest` — последний завершённый запуск каждого hostname;
- `--include-partial` — допускает `.wua.partial` и незавершённые запуски.

`--all` и `--latest` взаимоисключающие.

## 18. Текущие выходы парсера

Парсер создаёт:

- `users.csv`
- `password_policies.csv`
- `interfaces.csv`
- `routes.csv`
- `firewall.csv`
- `netstat.csv`
- `ping.csv`
- `http.csv`
- `diagnostics.csv`
- `runs.csv`
- `parser_errors.csv`

Отдельный `systems.csv` **не создаётся**.

SYSTEM остаётся в исходном логе и учитывается в `runs.csv`.

## 19. Служебные поля CSV парсера

В экспортируемые наборы добавляются служебные колонки:

- `Идентификатор запуска`
- `Имя исходного файла`
- `Статус запуска`
- `Версия формата`
- `Версия схемы`
- `Время начала запуска`
- `Время окончания запуска`
- `Лог завершён`

Далее добавляются колонки из схем WUA1.

При нескольких версиях схем формируется объединение колонок в порядке первого появления.

Отсутствующее поле получает:

`Не определено`

## 20. Валидация парсером

Текущий парсер проверяет, среди прочего:

- BOM UTF-16;
- FILE первой записью;
- повторный FILE;
- SCHEMA;
- соответствие DATA схеме;
- число полей;
- run ID;
- EVENT из 10 полей;
- END;
- неизвестные DATA-типы;
- неизвестные виды записей;
- повреждённые CSV-строки.

Ошибки отдельных строк и файлов изолируются и попадают в:

`parser_errors.csv`

## 21. runs.csv

Содержит сведения обо всех найденных запусках:

- run ID;
- hostname;
- файл и путь;
- формат;
- версия WinUsersAudit;
- ОС;
- времена начала/окончания;
- наличие END;
- статус;
- полнота;
- количества записей типов;
- предупреждения;
- ошибки;
- результат структурной проверки;
- причину выбора/пропуска.

## 22. Тесты

Запуск:

`python3 -m unittest discover -s tests -v`

Текущие тесты проверяют:

- нормальный WUA1;
- Unicode и спецсимволы;
- наличие всех файлов экспорта;
- отсутствие `systems.csv`;
- незавершённые `.log`;
- `.partial`;
- `--all`;
- `--latest`;
- объединение разных версий схем без смещения колонок;
- неизвестные типы;
- повреждённые DATA;
- повреждённую CSV-строку;
- взаимоисключение `--all`/`--latest`;
- наличие совместимого WMI-запроса ОС в сборщике;
- одну PING-строку на адрес;
- USER schema 2 с параметрами парольной политики.

## 23. Что НЕ следует считать реализованным

На текущем состоянии ветки не следует утверждать, что:

- установленное ПО собирается;
- `password_policies.csv` удалён;
- парольная политика существует только в `users.csv`;
- unified-report полностью синхронизирован с `main`;
- отдельный software DATA type уже существует.

Если эти изменения нужны, это новая задача и изменение текущей реализации.

## 24. Изоляция веток

Не переносить изменения между `main` и `unified-report` автоматически.

Если нужно перенести функцию из `main`, сначала адаптировать её к:

- WUA1;
- SCHEMA/DATA;
- EVENT;
- схеме версионирования;
- парсеру;
- тестам.

Не копировать многофайловую логику `main` как есть.
