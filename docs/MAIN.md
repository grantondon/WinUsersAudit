# WinUsersAudit — фактическое состояние ветки `main`

Документ составлен по текущим `README.md` и `WinUsersAudit.vbs` ветки `main`.

## 1. Назначение ветки

`main` — классическая рабочая версия WinUsersAudit.

Она формирует отдельные отчёты CSV, диагностический лог и общий ZIP.

Пользовательских ключей запуска нет.

Обычный запуск:

`cscript WinUsersAudit.vbs`

При каждом запуске выполняется полный аудит.

## 2. Выходные файлы

Текущая версия создаёт пять CSV:

- `<hostname>_user.csv`
- `<hostname>_int.csv`
- `<hostname>_route.csv`
- `<hostname>_netstat.csv`
- `<hostname>_software.csv`

Также:

- `<hostname>_diag.log`
- `<hostname>.zip`

Файлы создаются рядом со скриптом.

При повторном запуске текущие файлы с теми же именами перезаписываются.

ZIP содержит пять CSV и диагностический лог.

Исходные файлы после успешной архивации сохраняются.

## 3. Основной порядок выполнения

Текущий основной сценарий выполняет следующие этапы:

1. создаёт `FileSystemObject` и `WScript.Shell`;
2. определяет hostname;
3. проверяет внутренний ADSI worker через окружение;
4. формирует пути выходных файлов;
5. запускает диагностический лог;
6. подключается к `root\cimv2`;
7. определяет версию ОС;
8. собирает сведения о компьютере;
9. проверяет синхронизацию времени;
10. проверяет автоматическую защиту сеанса;
11. получает парольную и локальную классическую политику аудита;
12. создаёт отчёт сетевых интерфейсов;
13. создаёт отчёт маршрутов;
14. получает состояние брандмауэра;
15. создаёт отчёт TCP/UDP соединений;
16. создаёт отчёт установленного ПО;
17. выполняет проверку Интернета;
18. получает пользовательские ADSI-данные;
19. формирует `_user.csv`;
20. завершает диагностику;
21. создаёт ZIP;
22. дописывает результат архивации в лог;
23. выводит пути файлов в консоль.

11. `Пароль можно изменить?`
12. `Срок действия пароля истекает?`
13. `Пароль просрочен?`
14. `УЗ отключена?`
15. `УЗ заблокирована?`
16. `Последний вход`
17. `Окончание действия УЗ`
18. `Число неудачных входов`

25. `Время блокировки`
26. `Время сброса счётчика ошибочных входов`

Последние параметры политики повторяются для каждой строки пользователя.

### Специальные значения

- последний вход отсутствует → `Не входил`;
- бессрочная учётная запись → `Не ограничено`;
- недоступное свойство → `Не определено`;
- история паролей = 0 → `Нет`;
- время блокировки = 0 → `До разблокировки администратором`.

### Возраст пароля

Источник: ADSI WinNT `PasswordAge`.

Формат:

`N дней HH часов MM минут SS секунд`

Получение ADSI-данных изолировано дочерним `cscript` с тайм-аутом 30 секунд.

## 8. `<hostname>_software.csv`

Текущая ветка `main` реально собирает установленное ПО.

Источники:

`Microsoft\Windows\CurrentVersion\Uninstall`

Проверяются:

- системные записи;
- загруженные пользовательские разделы;
- 32-битное представление;
- 64-битное представление на 64-разрядной Windows.

`Win32_Product` не используется.

Текущие 12 колонок:

1. `hostname`
2. `Название ПО`
3. `Версия`
4. `Издатель`
5. `Дата установки`
6. `Путь установки`
7. `Размер, КБ`
8. `Область установки`
9. `Пользователь`
10. `Разрядность`
11. `Системный компонент`
12. `Тип выпуска`

Особенности:

- запись без `DisplayName` пропускается;
- системная установка: пользователь `Все пользователи`;
- `InstallDate` вида `ГГГГММДД` преобразуется в `ГГГГ-ММ-ДД`;
- portable ПО без Uninstall-записи не определяется;
- незагруженные пользовательские профили могут быть недоступны.

## 9. Парольная и локальная классическая политика аудита

Используется `secedit.exe`.

Скрипт диагностирует:

- запуск;
- код завершения;
- существование INF;
- содержимое/наличие `[System Access]` и `[Event Audit]`;
- источник данных;
- ошибки.

В текущей документации отдельно отмечено, что используется обычный `/export` без `/mergedpolicy`, поскольку это устраняло наблюдавшуюся проблему на проверенной Windows XP x64.

Для полноценного результата рекомендуются административные права.

Классическая политика аудита выводится только в `_diag.log` и использует тот
же экспорт `secedit /export /areas SECURITYPOLICY`, что и парольная политика:
второй `secedit` не запускается. Разбираются девять параметров `[Event Audit]`:
`AuditSystemEvents`, `AuditLogonEvents`, `AuditObjectAccess`,
`AuditPrivilegeUse`, `AuditProcessTracking`, `AuditPolicyChange`,
`AuditAccountManage`, `AuditDSAccess` и `AuditAccountLogon`.

Коды `0` и `4` означают «Аудит отключён», `1` — «Успех», `2` — «Отказ»,
`3` — «Успех и отказ». Отсутствующий или неизвестный параметр выводится как
«Не определено»; это не равнозначно отключению аудита.

Источник политик определяется по уже полученным `Domain`, `PartOfDomain` и
`DomainRole` из `Win32_ComputerSystem`: для автономной рабочей станции/сервера
указывается «Локальные политики», для члена домена и контроллера домена —
«Локальные и доменные политики». Во втором случае журнал предупреждает лишь о
возможности переопределения локальных настроек доменными политиками; конкретная
GPO и результирующая политика не определяются.

## 10. Брандмауэр

Результат записывается в `_diag.log`.

На Vista и новее:

`HNetCfg.FwPolicy2`

На XP SP2 / Server 2003:

`HNetCfg.FwMgr`

Диагностика включает службы брандмауэра и профильную информацию.

Состояние службы не следует трактовать как единственный показатель фактической фильтрации.

## 11. Проверка Интернета

Выполняются:

- 5 ICMP-проверок;
- 5 синхронных HTTP-проверок через `WinHttp.WinHttpRequest.5.1`.

Результаты записываются в `_diag.log`.

Наличие хотя бы одного HTTP-ответа трактуется как подтверждение доступа.

Если HTTP не отвечает, но ICMP проходит, итог может быть `Не определено`.

## 12. Автоматическая защита сеанса

Текущий `main` уже собирает эту диагностику.

Проверяются:

- `InactivityTimeoutSecs` для Windows 8 / Server 2012 и новее;
- настройки защищённой заставки загруженных пользовательских профилей;
- тайм-аут;
- запрос учётных данных;
- путь к заставке;
- наличие файла заставки.

Итоговый подтверждённый тайм-аут — минимальный из действующих механизмов.

На XP/Server 2003 результат определяется по защищённой заставке, поскольку современная системная политика бездействия там не поддерживается.

## 13. Синхронизация времени

В `_diag.log` записываются состояние службы `W32Time`, эффективные параметры
`Type`, `NtpServer`, `Enabled` и `SpecialPollInterval` с учётом приоритета
групповой политики. Режимы `NT5DS`, `NTP`, `AllSync` и `NoSync` переводятся в
понятное описание способа ведения времени.

Дополнительно выполняются только читающие запросы `w32tm /query /source`,
`/status` и `/peers` с тайм-аутом. На XP/Server 2003 отсутствие поддержки
`/query` считается ожидаемым и используется результат чтения службы и реестра.
Принудительная синхронизация не запускается.

## 14. Системная диагностика

Текущий код записывает, среди прочего:

- WSH;
- путь скрипта;
- текущую папку;
- пользователя запуска;
- TEMP/SystemRoot;
- архитектуру окружения;
- ОС, версию, Service Pack;
- время последней загрузки;
- дату установки ОС;
- домен/рабочую группу;
- роль компьютера;
- производителя;
- модель;
- объём RAM;
- текущего интерактивного пользователя;
- этапы и длительность выполнения;
- ошибки;
- сведения о сформированных файлах.

Не следует считать уже реализованными BIOS/CPU/диски/Windows Update и другие идеи, если их нет в актуальном коде.

## 15. ZIP

Используется `Shell.Application`.

Пустой ZIP создаётся вручную, после чего файлы добавляются через `CopyHere`.

Добавляются:

- user CSV;
- interfaces CSV;
- routes CSV;
- netstat CSV;
- software CSV;
- диагностический лог.

Добавление асинхронное, поэтому скрипт проверяет появление файла в архиве и его размер.

Для одного файла предусмотрено до 120 проверок по 250 мс.

Если архивирование неполное, ZIP удаляется, исходные отчёты сохраняются.

## 16. Кодировка

CSV и диагностика:

- UTF-16 LE с BOM;
- CSV-разделитель `;`;
- значения заключаются в двойные кавычки.

## 17. Критические факты для дальнейшей разработки

Не возвращать старые предположения:

- CSV сейчас пять, а не четыре;
- `_software.csv` — текущий рабочий отчёт;
- `_int.csv` сейчас 15 колонок;
- пользовательский CSV сейчас 26 колонок;
- пользовательских `/debug`, `/nolog` и других ключей в `main` нет;
- установленное ПО уже реализовано, это не «планируемая функция».
