# WinUsersAudit — контекст проекта

## 1. Назначение

WinUsersAudit собирает сведения о конфигурации и состоянии компьютера Windows
штатными средствами операционной системы. Сборщик не изменяет учётные записи и
настройки безопасности, не считывает пароли и их хэши.

Основной файл — `WinUsersAudit.vbs`. Рабочая ветка — `main`.

## 2. Совместимость

Целевые системы:

- Windows XP SP2;
- Windows Server 2003;
- Windows 7;
- Windows 10;
- более новые версии Windows при наличии используемых системных интерфейсов.

Сборщик использует WSH/VBScript, WMI, ADSI WinNT, COM, реестр и штатные
утилиты Windows. Он не требует PowerShell, .NET, WMIC, Python, сторонних
программ или дополнительных установок.

## 3. Результаты запуска

При каждом запуске создаются:

1. `<hostname>_user.csv` — локальные учётные записи и парольная политика;
2. `<hostname>_int.csv` — сетевые интерфейсы;
3. `<hostname>_route.csv` — таблица маршрутизации IPv4;
4. `<hostname>_netstat.csv` — прослушиваемые порты и соединения IPv4;
5. `<hostname>_software.csv` — установленное ПО;
6. `<hostname>_diag.log` — диагностика выполнения и системные сведения;
7. `<hostname>.zip` — пять CSV и диагностический журнал.

Файлы создаются рядом со скриптом и при повторном запуске перезаписываются.
Исходные отчёты после архивации сохраняются.

## 4. Основные разделы сбора

- версия ОС и сведения о компьютере;
- синхронизация времени Windows;
- автоматическая защита сеанса после бездействия;
- локальная парольная политика через `secedit.exe`;
- локальные пользователи через WMI и ADSI WinNT;
- сетевые интерфейсы и IPv4-маршруты;
- состояние встроенного брандмауэра;
- IPv4 TCP/UDP соединения и сведения о процессах;
- установленное ПО из разделов Uninstall реестра;
- пять ICMP- и пять HTTP-проверок доступности Интернета;
- создание ZIP штатным `Shell.Application`.

IPv6 не включается в сетевые отчёты.

## 5. Устойчивость

- Ошибка отдельного некритического раздела не должна останавливать аудит.
- Потенциально зависающий ADSI WinNT выполняется в дочернем `cscript` с
  тайм-аутом.
- Запуски `netstat.exe` и читающие запросы `w32tm.exe` ограничены тайм-аутами.
- Конфигурации сетевых адаптеров предварительно загружаются одним WMI-запросом.
- Реестр установленного ПО читается без `Win32_Product`.
- При неполной архивации ZIP удаляется, а исходные отчёты сохраняются.
- Диагностический журнал фиксирует этапы, длительность, ошибки и состояние
  созданных файлов.

## 6. Кодировки

`WinUsersAudit.vbs` и `WinUsersAudit_README.txt` хранятся в UTF-16 LE с BOM.
Создаваемые CSV и `_diag.log` также имеют UTF-16 LE с BOM. CSV используют `;`
и двойные кавычки для каждого значения.

## 7. Документация и проверка

- `README.md` — инструкция пользователя на GitHub;
- `WinUsersAudit_README.txt` — офлайн-инструкция для целевого компьютера;
- `docs/MAIN.md` — подробное техническое описание текущей реализации;
- `docs/LOCAL_WORKFLOW.md` — порядок разработки и проверки;
- `AGENTS.md` — постоянные ограничения для Codex;
- `tools/Test-LocalAudit.ps1` — вспомогательная проверка на Windows.

Фактический код имеет приоритет над документацией при обнаружении расхождения.
