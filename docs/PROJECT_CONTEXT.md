# WinUsersAudit — контекст проекта

## 1. Назначение

WinUsersAudit — переносимый сборщик сведений о конфигурации и состоянии
компьютера Windows, работающий штатными средствами операционной системы.

Основной исполняемый файл — `WinUsersAudit.vbs`. Рабочая ветка — `main`.

Сборщик предназначен для аудита и не должен изменять учётные записи или
настройки безопасности, считывать пароли либо хэши паролей.

## 2. Целевые системы

Проект должен сохранять совместимость с:

- Windows XP SP2;
- Windows Server 2003;
- Windows 7;
- Windows 10;
- более новыми Windows, пока необходимые старые системные интерфейсы доступны.

Ключевой принцип проекта — отсутствие дополнительных зависимостей на
проверяемом компьютере. Сборщик использует WSH/VBScript, WMI, ADSI WinNT, COM,
реестр и штатные утилиты Windows. Он не должен требовать PowerShell, .NET,
WMIC, Python, сторонних программ или дополнительных установок.

## 3. Архитектурные принципы

- Один запуск выполняет полный аудит и формирует набор отдельных отчётов и
  диагностический журнал.
- Ошибка отдельного некритического раздела по возможности не должна
  останавливать остальные разделы.
- Предпочтительны структурированные источники данных: WMI, ADSI, COM и реестр.
  Разбор локализованного консольного вывода применяется только при
  необходимости.
- Потенциально зависающие или нестабильные операции должны иметь защиту от
  бесконечного ожидания.
- IPv6 сейчас не является целью проекта.
- Установленное ПО определяется по реестру, без `Win32_Product`.
- Сборщик не имеет пользовательских ключей запуска.

Конкретные текущие отчёты, колонки, источники данных и детали реализации
описаны в `docs/MAIN.md`.

## 4. Структура репозитория

- `WinUsersAudit.vbs` — production-сборщик и главный источник истины о
  фактическом поведении;
- `README.md` — пользовательская инструкция на GitHub;
- `WinUsersAudit_README.txt` — офлайн-инструкция для целевого компьютера;
- `AGENTS.md` — постоянные правила и ограничения для Codex;
- `docs/MAIN.md` — техническая карта фактического состояния ветки `main`;
- `docs/LOCAL_WORKFLOW.md` — локальная разработка, проверка и публикация;
- `tools/Test-LocalAudit.ps1` — вспомогательный сценарий проверки на Windows,
  не являющийся зависимостью сборщика.

## 5. Источники истины

При расхождении источников используй следующий приоритет:

1. поставленная пользователем задача;
2. фактический актуальный код `WinUsersAudit.vbs`;
3. `AGENTS.md` для постоянных ограничений разработки;
4. `docs/MAIN.md` для описания текущей реализации;
5. пользовательские README.

Расхождение между кодом и документацией нужно явно фиксировать и исправлять,
если это относится к выполняемой задаче.

## 6. Кодировки

Production-файлы и создаваемые отчёты имеют требования к кодировке, критичные
для старых Windows. Конкретные правила зафиксированы в `AGENTS.md` и должны
соблюдаться при любых изменениях.

## 7. Как использовать этот документ

Этот файл нужен для понимания назначения и общих архитектурных ограничений
проекта. Он не является каталогом текущих колонок, функций или форматов
отчётов.

Для локальной задачи Codex не обязан перечитывать этот документ, если
достаточно `AGENTS.md`, затрагиваемого кода и соответствующего раздела
`docs/MAIN.md`.
