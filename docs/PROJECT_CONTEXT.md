# WinUsersAudit — актуальный контекст проекта

Этот документ описывает фактическую структуру проекта после повторной сверки с текущими версиями файлов в GitHub.

## 1. Назначение

WinUsersAudit — проект для сбора сведений о конфигурации и состоянии Windows штатными средствами ОС.

Основной сборщик написан на VBScript и рассчитан на Windows XP/Server 2003 и более новые версии Windows.

Проект не изменяет учётные записи и настройки безопасности и не считывает пароли.

## 2. Репозиторий

Репозиторий:

`grantondon/WinUsersAudit`

Основной файл сборщика:

`WinUsersAudit.vbs`

В репозитории две независимые ветки:

- `main`;
- `unified-report`.

## 3. Текущее состояние `main`

`main` — классическая версия.

При каждом обычном запуске выполняется полный аудит без пользовательских ключей запуска.

Создаются:

1. `<hostname>_user.csv`
2. `<hostname>_int.csv`
3. `<hostname>_route.csv`
4. `<hostname>_netstat.csv`
5. `<hostname>_software.csv`
6. `<hostname>_diag.log`
7. `<hostname>.zip`

ZIP содержит пять CSV и диагностический лог.

Основные разделы:

- локальные пользователи;
- парольная политика;
- сетевые интерфейсы;
- IPv4-маршруты;
- брандмауэр;
- IPv4 TCP/UDP соединения;
- установленное ПО;
- ping/HTTP-проверки;
- системная диагностика;
- защита сеанса после бездействия.

Подробности: `MAIN.md`.

## 4. Текущее состояние `unified-report`

`unified-report` — отдельная экспериментальная архитектура.

Сборщик создаёт один файл:

`<hostname>_YYYYMMDD_HHMMSS.wua.log`

Во время работы используется:

`*.wua.partial`

Формат: `WUA1`.

Классические CSV, `_diag.log` и ZIP в основном пути выполнения этой ветки не создаются.

В ветке есть отдельный Python-парсер:

`parse_wua_logs.py`

и тесты:

`tests/test_parse_wua_logs.py`

Python нужен только на компьютере обработки логов. На проверяемом Windows-хосте Python не нужен.

Подробности: `UNIFIED_REPORT.md`.

## 5. Ключевое различие веток

`main` функционально новее в части установленного ПО и части системной диагностики.

Текущая `unified-report` не содержит отдельного типа SOFTWARE и не переносит текущее ПО-инвентаризирование из `main`.

Не предполагай, что функционал веток синхронизирован.

## 6. Совместимость

Для VBScript-сборщика обязательна ориентация на:

- Windows XP SP2;
- Windows Server 2003;
- последующие Windows.

Сборщик использует штатные механизмы Windows:

- WSH/VBScript;
- WMI;
- ADSI WinNT;
- COM;
- `secedit.exe`;
- `netstat.exe`;
- `ping.exe`;
- WinHTTP;
- встроенные firewall COM API;
- Shell ZIP в `main`.

Не использовать на проверяемой машине PowerShell, .NET, WMIC, curl, Python и сторонние утилиты.

## 7. Парольная политика

Политика компьютера считывается один раз и используется при формировании данных пользователей.

Среди текущих параметров `main`:

- максимальный срок действия пароля;
- минимальная длина;
- минимальный срок действия;
- сложность;
- история паролей;
- порог блокировки;
- время блокировки;
- время сброса счётчика.

`secedit.exe` используется с диагностированием результата.

Недоступное значение выводится как `Не определено`.

## 8. Возраст пароля

Возраст пароля читается через ADSI WinNT `PasswordAge`.

Формат:

`N дней HH часов MM минут SS секунд`

Нулевое значение допустимо и не означает отсутствие пароля.

В текущем `main` ADSI-сбор выполняется отдельным `cscript`-процессом с тайм-аутом 30 секунд, чтобы зависший WinNT provider не остановил основной аудит.

В `main` внутренний worker определяется через унаследованное окружение, без пользовательских ключей запуска.

В `unified-report` сохранён отдельный внутренний password-age worker.

## 9. Поле «Пароль требуется?»

`Пароль требуется?` — флаг обязательности пароля для учётной записи.

Он не доказывает:

- что пароль установлен;
- что пароль отсутствует;
- что текущий пароль соответствует политике.

Это важно сохранять и в коде, и в документации.

## 10. Изоляция ошибок

Проект стремится продолжать сбор после локальных ошибок разделов.

Критические ранние ошибки, например невозможность создать базовые COM-объекты или подключиться к WMI, могут завершить выполнение.

Остальные разделы должны по возможности фиксировать ошибку и продолжать работу.
