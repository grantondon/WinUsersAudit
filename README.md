# WinUsersAudit

Аудит локальных учетных записей, парольной политики, сетевых интерфейсов и таблицы маршрутизации Windows без PowerShell.

**Файлы:** [скрипт WinUsersAudit.vbs](WinUsersAudit.vbs) · [инструкция для Блокнота](WinUsersAudit_README.txt).

Для загрузки файлов используйте **Code → Download ZIP** и распакуйте архив. Скрипт и TXT сохранены в UTF-16 LE с BOM; не пересохраняйте `.vbs` в UTF-8 перед запуском на старых Windows.

Для версии скрипта с отметкой diagnostic revision 11

## 1. Назначение

Скрипт собирает сведения о локальных учетных записях Windows, парольной
политике компьютера, сетевых интерфейсах и таблице маршрутизации IPv4.
Результаты сохраняются в отдельных CSV-файлах для просмотра в Excel.

Собираются в том числе встроенные, переименованные и отключенные учетные
записи. Встроенный администратор определяется по SID, оканчивающемуся на -500.
Доменные учетные записи в основной список не включаются.

Скрипт не изменяет учетные записи и настройки безопасности. Сами пароли
не считываются и не записываются в отчет или журнал.

## 2. Требования и подготовка

Скрипт рассчитан на Windows XP, Windows Server 2003 и более поздние версии
Windows. Используются штатные Windows Script Host/VBScript, WMI и secedit.exe.
PowerShell и установка дополнительных компонентов не требуются, если эти
штатные средства присутствуют и разрешены в системе.

Для получения парольной политики нужны права администратора. В отдельных
редакциях или версиях Windows secedit может отсутствовать либо не выгружать
нужные параметры. В таком случае они будут отмечены как «Не определено».

1) Скопируйте WinUsersAudit.vbs в отдельную папку, например C:\Audit.
2) Убедитесь, что расширение файла — .vbs, а не .vbs.txt.
3) Убедитесь, что в папку можно записывать файлы.
4) Перед повторным запуском закройте предыдущий CSV в Excel.

Не требуется устанавливать скрипт или менять его содержимое.

## 3. Запуск

**Windows XP и Windows Server 2003:**
Войдите под учетной записью с правами администратора. Откройте «Пуск» →
«Выполнить», введите cmd и нажмите Enter.

**Windows Vista и более поздние версии:**
Найдите cmd в меню «Пуск», нажмите правой кнопкой мыши и выберите
«Запуск от имени администратора». Подтвердите запрос UAC.
Членство учетной записи в группе администраторов само по себе не заменяет
запуск командной строки с повышенными правами.

В командной строке перейдите в папку со скриптом:

    cd /d C:\Audit

Если в пути есть пробелы, используйте кавычки:

    cd /d "C:\Мои документы\Audit"

Выполните обычный запуск:

    cscript //nologo WinUsersAudit.vbs

По умолчанию создаются три CSV, файл диагностики и общий ZIP-архив.
Не запускайте скрипт двойным щелчком: сообщения могут появляться отдельными
диалоговыми окнами вместо вывода в командной строке.

## 4. Запуск без диагностики

Чтобы отключить диагностику и проверку Интернета, укажите ключ /nolog:

    cscript //nologo WinUsersAudit.vbs /nolog

При этом сведения об ОС, пользователях, парольной политике, интерфейсах и
маршрутах собираются как обычно. Проверка Интернета не выполняется. Ранее
созданный файл диагностики не удаляется, не обновляется и не включается в архив.

Старый ключ /debug остается допустимым, но больше не нужен: диагностика
уже включена по умолчанию. Если указаны /debug и /nolog, журнал отключается.

Параметр //nologo относится к cscript и скрывает его приветственный текст.
Ключ /nolog относится к скрипту и отключает файл диагностики.

## 5. Где находятся результаты

Файлы создаются рядом со скриптом, независимо от текущей папки командной
строки. Имя файлов соответствует имени компьютера.

Например, при запуске на PC-01 из папки C:\Audit:

    C:\Audit\PC-01_user.csv
    C:\Audit\PC-01_int.csv
    C:\Audit\PC-01_route.csv
    C:\Audit\PC-01_diag.log
    C:\Audit\PC-01.zip

При повторном обычном запуске все файлы перезаписываются. ZIP содержит три CSV
и диагностику. При запуске с /nolog архив содержит только три CSV. Исходные
файлы после архивации сохраняются рядом со скриптом.

В консоли отображаются имя компьютера, количество найденных локальных
учетных записей, имя встроенного администратора, пути результатов и ошибки.

Диагностический файл содержит время запуска и завершения, версию WSH, путь и
аргументы скрипта, учетную запись запуска, системные пути и архитектуру,
версию ОС, этапы выполнения, сведения secedit, результаты проверки Интернета,
количество обработанных объектов, пути и размеры отчетов и все перехваченные
ошибки. Его следует сохранять для диагностики проблем выполнения.

CSV и диагностика записываются в Unicode UTF-16 LE с BOM. CSV использует
разделитель «точка с запятой»; значения заключены в двойные кавычки.

## 6. Просмотр CSV

Откройте CSV в Microsoft Excel. Если все данные оказались в одном столбце
или русские буквы отображаются неправильно, используйте мастер импорта
текстовых файлов и задайте:

    Кодировка: Unicode UTF-16 LE.
    Разделитель: точка с запятой (;).
    Ограничитель текста: двойная кавычка (").

Группы внутри одной ячейки разделены запятыми.

## 7. Состав отчета

Одна строка CSV соответствует одной локальной учетной записи.
Столбцы расположены в следующем порядке:

| № | Столбец | Описание |
|---|---|---|
| 1 | Компьютер или домен | значение Domain учетной записи; для локальных пользователей обычно соответствует имени компьютера. |
| 2 | Версия ОС | название Windows, номер версии и Service Pack, если указан. |
| 3 | Название учетной записи | имя локального пользователя. |
| 4 | Описание | описание учетной записи; может быть пустым. |
| 5 | Локальная учетная запись | признак локальной учетной записи. |
| 6 | SID | идентификатор безопасности учетной записи. |
| 7 | Членство в локальных группах | прямое членство; вложенные группы и эффективные права не рассчитываются. Список может быть пустым. |
| 8 | Пароль требуется | флаг обязательности пароля для учетной записи. |
| 9 | Возраст пароля | время с момента последней установки или смены пароля по данным ADSI WinNT `PasswordAge`; например, «12 дней 03 часа 15 минут 42 секунды». |
| 10 | Пароль можно изменить | разрешение пользователю менять свой пароль. |
| 11 | Срок действия пароля истекает | включено ли истечение срока пароля. |
| 12 | Учетная запись отключена | признак отключенной учетной записи. |
| 13 | Учетная запись заблокирована | состояние блокировки по данным WMI. |
| 14 | Максимальный срок действия пароля (дней, политика) | число дней либо «Не ограничен». |
| 15 | Минимальная длина пароля (символов, политика) | минимальное число символов. |
| 16 | Минимальный срок действия пароля (дней, политика) | минимальный интервал до следующей смены пароля пользователем. |
| 17 | Требования сложности пароля включены (политика) | «Да» или «Нет». |
| 18 | Требования неповторяемости паролей включены (политика) | «Да», если размер истории паролей больше нуля; при истории 0 — «Нет». |

При недоступности логического свойства или параметра политики выводится
«Не определено». Это не означает, что настройка отключена.

### Важно при чтении результатов

«Пароль требуется: Нет» не означает, что пароль отсутствует. Это значение
флага учетной записи, а не проверка установленного пароля.

«Возраст пароля: 0 дней 00 часов 00 минут 00 секунд» является корректным
нулевым значением `PasswordAge` и не означает, что пароль отсутствует.

«Срок действия пароля истекает: Да» не означает, что пароль уже просрочен.
Столбец показывает, включено ли для пользователя истечение срока пароля.

Последние пять столбцов описывают общую политику компьютера и повторяются
в каждой строке. Если для пользователя истечение срока пароля отключено,
общий максимальный срок к его паролю не применяется.

Наличие требований длины и сложности не доказывает, что уже установленный
пароль им соответствует. Скрипт не проверяет содержимое паролей.

## 8. Сетевые интерфейсы

Файл `<имя компьютера>_int.csv` содержит отдельную строку для каждого
экземпляра `Win32_NetworkAdapter`, включая отключенные физические и виртуальные
адаптеры, а также адаптеры без включенного TCP/IP. Сетевая конфигурация
сопоставляется с адаптером через `Win32_NetworkAdapterConfiguration.Index`.

| № | Столбец |
|---|---|
| 1 | hostname |
| 2 | Имя подключения |
| 3 | Описание |
| 4 | Индекс интерфейса |
| 5 | MAC-адрес |
| 6 | Состояние подключения |
| 7 | TCP/IP включён |
| 8 | IP-адрес |
| 9 | Маска подсети |
| 10 | Основной шлюз |
| 11 | DNS-серверы, в порядке использования |
| 12 | DHCP включён |
| 13 | DHCP-сервер |
| 14 | Получение аренды |
| 15 | Окончание аренды |

Если интерфейсу назначено несколько адресов, масок, шлюзов или DNS-серверов,
они перечисляются в одной ячейке через запятую. DNS-серверы сохраняются в
порядке, возвращенном WMI. Для отключенных или ненастроенных интерфейсов часть
полей может быть пустой, а состояние — «Не определено», если старая версия WMI
не предоставляет соответствующее свойство.

## 9. Таблица маршрутизации

Файл `<имя компьютера>_route.csv` содержит отдельную строку для каждого
маршрута IPv4, возвращенного WMI-классом `Win32_IP4RouteTable`.

| № | Столбец | Свойство WMI |
|---|---|---|
| 1 | hostname | имя компьютера |
| 2 | Сеть назначения | `Destination` |
| 3 | Маска | `Mask` |
| 4 | Следующий узел | `NextHop` |
| 5 | Имя подключения | сопоставляется с `_int.csv` по индексу интерфейса |
| 6 | Индекс интерфейса | `InterfaceIndex` |
| 7 | Метрика | `Metric1` |

Отчет содержит таблицу маршрутизации IPv4, доступную операционной системе на
момент запуска. Маршруты IPv6 в этот файл не включаются.

## 10. Проверка Интернета

При включенной диагностике выполняются пять ICMP-проверок через `ping.exe` и
пять синхронных HTTP-запросов через `WinHttp.WinHttpRequest.5.1`. Для каждого
ресурса в `<имя компьютера>_diag.log` записывается результат, а затем
количество успешных проверок и итоговое заключение.

Наличие хотя бы одного HTTP-ответа подтверждает доступ к Интернету. Если HTTP
не отвечает, но ICMP проходит, результат отмечается как «Не определено»:
отдельные сети и ресурсы могут блокировать один из протоколов. При /nolog эти
проверки не выполняются.

## 11. ZIP-архив

Архив `<имя компьютера>.zip` создается штатным компонентом сжатых папок
Windows через `Shell.Application`; сторонний архиватор не требуется. Скрипт
ожидает завершения асинхронного копирования и проверяет имя и размер каждого
файла. Если компонент недоступен или архив получился неполным, ZIP удаляется,
а исходные отчеты сохраняются.

## 12. Возможные ошибки

Код secedit 740
Требуется повышение прав. На Vista и более поздних версиях закройте обычную
командную строку и откройте новую через «Запуск от имени администратора».

Не удалось создать CSV или диагностический файл
Закройте CSV в Excel. Проверьте права записи в папку и отсутствие атрибута
«Только чтение» у существующего файла. При необходимости используйте другую
доступную папку для скрипта.

Ошибка подключения к WMI
Проверьте, что служба «Инструментарий управления Windows» запущена.
При сохранении ошибки передайте администратору текст из консоли.

Парольная политика — «Не определено»
Запустите скрипт без /nolog и проверьте диагностику. Возможные причины:
недостаточные права, отсутствие secedit, ошибка экспорта или отсутствие
нужных ключей в полученном INF.

Код secedit 0, но нет [System Access]
Успешный код завершения не гарантирует наличие нужных данных в экспорте.
В текущем скрипте используется обычный /export без /mergedpolicy, что
устранило наблюдавшуюся проблему на проверенной Windows XP x64.
Если ошибка повторилась, передайте новый журнал с версиями ОС и secedit.
Не изменяйте парольную политику и не запускайте команды ее импорта ради
устранения ошибки чтения отчета.

Скрипт не запускается или не появляется диагностика
Проверьте расширение файла и сообщения cscript. Если выполнение VBScript
или WSH запрещено политиками организации, обратитесь к администратору.
При ошибке до начала сбора политики диагностический файл может не появиться.

ZIP не создан
Проверьте, что служба оболочки Windows и компонент сжатых ZIP-папок доступны.
CSV и диагностика при ошибке архивации не удаляются.

## 13. Что передать для разбора ошибки

1) Выполните запуск без /nolog.
2) Сохраните сообщения из командной строки.
3) Передайте `<имя компьютера>_diag.log` и текст ошибки.
4) При ошибке в значениях приложите соответствующую часть CSV и, если
   возможно, снимок окна с настройками Windows для сравнения.

Перед отправкой учитывайте, что отчет содержит имена пользователей,
группы и SID, а диагностика — имя компьютера и системные пути. При
необходимости обезличьте эти сведения. Пароли отправлять не нужно.
